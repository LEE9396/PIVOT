## 1. 원래 연구 방향 (`main.pdf` 08/18)

**한 문장**: 관절체의 부위별 밀도와 형상을 실세계 능동 로봇 조작으로 추정해,
외형과 동역학이 모두 충실한 sim-ready asset 을 만든다.

```
   part 단위 articulated 3DGS 재구성
        ↓
   정적 손목 F/T 를 밀도 벡터의 선형 구속으로 정식화
        ↓
   순차 베이지안 갱신
        ↓
   기대 정보이득이 가장 높은 관절 구성을 선택 (폐루프)
        ↓
   수렴하면 결과를 재구성된 asset 에 기록
```

**실험**: RGB-D 1대 + 로봇팔 + linkage gripper + **관절체 5종**

**Contribution 3개**
1. 최소 개입 파이프라인 — 실세계 관측·상호작용 → sim-ready 관절 asset
2. 능동 추정 전략 — 정보량 큰 관절 구성을 골라 null space 를 붕괴
3. 실물 5개 실험 — GT 밀도를 조절 가능한 시험 물체 포함

**상태**: Method / Experiments 는 **제목만 있고 본문 없음.** 이론 없음.
설계 근거는 `study_*.py` 여덟 개의 경험적 ablation.

## 3. 수정된 연구 방향

**한 문장**: 관절체의 부위별 밀도를 **추측이 아니라 측정으로** 알아내고,
그 측정에 최소 몇 번의 자세가 필요한지를 **재기 전에 계산해 실물로 확인**한 뒤,
결과를 sim-ready asset 에 기록한다.

### 무게중심이 바뀐 곳

```
   이전 :  "정확한 asset 을 만든다"
           → 정확도가 재구성 품질에 인질로 잡힘 (P2 가 직격)

   이후 :  "추측 대신 측정한다"
           → 주장이 상대적이 되어 재구성 품질과 분리됨
              VLM baseline 부위 질량오차 수십~수백 %
              우리 (부피오차 10% 포함)          약 6 %
```

**핵심**: 부피가 10% 틀려도 **측정이 추측을 압도합니다.** 그래서 P2 는
논문의 주장을 건드리지 못하고, **정량화된 가정**으로 Limitations 에 내려갑니다.

### 이론을 1번 기여로 추가

정보행렬을 닫힌 형태로 전개하면 세 가지가 나옵니다.

```
   ①  M(θ) = g²[ (3/σ_f²)·v vᵀ + (2/σ_τ²)·C(θ)ᵀC(θ) ]
       → 기울임 방향은 정보량에 무관   (설계공간 Θ×SO(3) → Θ)
       → M 에 ρ 가 없음               (폐루프가 필요한 이유는 각도 오차뿐)
       → 힘 채널은 저울과 중복         (구속 사양은 σ_τ)

   ②  rank M(θ) ≤ 4                  (중력 방향 개수·배치와 무관)
       null M(θ) = {총질량·1차모멘트를 보존하는 재분배}
       → 부위가 4개를 넘으면 한 자세로는 원리적으로 불가

   ③  R ≥ ⌈(P−1)/3⌉ ,  사슬은 ⌈(2p−2)/3⌉
       → 2-link 하한 1 = 관측 1,  3-link 하한 2 = 관측 2
```

> **표현 수위**: ① ② 는 고전 사실(정적 측정은 질량·무게중심만)을 **밀도
> 매개화로 옮긴 것**이므로 논문에서 *"we recall"* 로 씁니다. 새로 주장하는
> 것은 ③ 과, 그 재매개화가 만드는 **"부위 개수의 상한"** 이라는 귀결입니다.

### 실물 4개의 역할 분담

| 물체 | 역할 | 왜 |
| --- | --- | --- |
| **custom 2-link** | 하한 검증 (1 = 1) | CAD 라 부피 정확 |
| **custom 3-link** | **rank 천장 4가 실제로 구속** (미지수 5, 하한 2 = 관측 2) | ★ 이론 검증의 핵심 |
| **desk lamp** | 스캔 물체에서 파이프라인이 돈다는 시연 | 하한 검증엔 부적합 (조건수 간극) |
| **laptop** | 야생 물체 + **부위 귀속** 검증 (기지 추 50 g 차분) | 부피와 무관한 검증 |

**라운드 수는 부피 오차에 안 흔들립니다** — 30% 를 넣어도 2-link 1, 3-link 2 유지.
그래서 **이론 검증은 재구성 품질과 원리적으로 분리됩니다.**

### 일반화는 물체를 늘리지 않고 시뮬레이션으로

`p≥4` 는 **물리적으로 만들 수 없습니다.** 마찰 힌지가 하류 전체를 버텨야 해서
`p=8` 은 5.31 N·m 가 필요하고, 그걸 견디려면 하류 밀도를 53 kg/m³ 로 낮춰야
합니다(3D 프린트 하한 250). 그래서 커스텀 물체의 치수 규칙을 이어붙인 합성
사슬 `p=2..8` 로 스윕합니다. `p=2,3` 이 실물과 정확히 일치하므로 확장이
신뢰됩니다.

## 5. 근거가 된 실측 수치 (전부 이 저장소에서 잼)

**이론 검증** — `study_theory.py`, 무작위 형상 300개
```
   닫힌 형태 vs 코드의 AᵀR⁻¹A      상대오차 7.9e-16
   삼면체 회전 불변성                상대오차 7.9e-16
   rank 천장 4                      위반 0회
   영공간 특성화                     7.5e-14
   실물 2link 미지수 3, rank 3, 하한 1 = 관측 1
   실물 3link 미지수 5, rank 4, 하한 2 = 관측 2
```

**기울임 방향 개수**
```
   1 방향 → rank 3      직교 2 방향 → rank 4 (천장)
   직교 3 방향 → rank 4 이지만 오차가 균등 (2:2:2)  ← 그래서 3방향
```

**재구성 오차의 영향** (3-link / desk lamp)
```
   부피 오차 10%  → 질량 5.9%,  밀도 13.2%
   부피 오차 50%  → 질량 32.8%, 밀도 225.6%
   램프 도심 1mm  → 질량 2.4%     램프 도심 2mm → 6.1%
```

**부피 오차와 라운드 수** — 이론 검증이 재구성 품질과 무관함을 보임
```
                 하한   부피 0%    부피 10%   부피 30%
   2-link 합성     1     1(4/4)    1(4/4)    1(3/4)
   3-link 합성     2     2(4/4)    2(3/4)    2(2/4)
   desk lamp      1     3(4/4)    7(4/4)    8(1/4)   ← 하한 검증에 부적합
```

**P≥5 의 벽은 센싱이 아니라 기하** — 두 스윕이 모두 부정
```
   상대 각도오차 10% → 0.25% (40배) : 벽이 한 칸만 이동 후 정지
   절대 각도하한 0.5° → 0.05° (10배) : 벽이 전혀 안 움직임
   p=5,6 에서 질량은 0.2~0.4% 로 정확하나 보고 반폭이 1.3~1.8% 에서 정체
   → 실패하는 것은 추정이 아니라 '인증'
```

**힌지 토크로 본 제작 가능성**
```
   p=3  0.496 N·m  → 하류 밀도 564 kg/m³   제작 가능
   p=4  1.157      → 242                  불가 (프린트 하한 250)
   p=8  5.305      →  53                  불가
```

### 6-2. 실물 측정 — **순서가 중요합니다**

```
   1순위  custom 2-link   미지수 3, 1 라운드.  가장 단순 → 파이프라인 디버깅용

   3순위  desk lamp       분해할 때 배수법으로 부위 부피도 실측

```

**커스텀 물체를 먼저 해야 합니다.** 이론 검증이 1번 기여이고, CAD GT 가
정확해서 파이프라인 오류를 여기서 걸러낼 수 있습니다. 램프·노트북을 먼저
하면 오차가 재구성 탓인지 코드 탓인지 못 가립니다.

> **최소 생존선**: 하드웨어가 늦어지면 **2-link 하나만이라도** 실물로 돌리십시오.
> 1 라운드면 끝나고, "이론 예측이 실물에서 맞는다" 는 한 점이라도 확보됩니다.

### 6-3. ⚠ 아직 아무도 시작 안 한 것 — Baseline

`4_exp.tex` 가 **PUGS · SiPhy · PhysX-Omni** 비교를 약속하고 있는데,
남의 코드를 세 개 세팅하는 일입니다. **각각 며칠씩 걸립니다.**

**우선순위를 이렇게 두시길 권합니다.**

```
   ① 우리 코드로 바로 되는 것  ← 가장 정보량이 크고 비용이 0
        · 강체 변형     : 물체를 덩어리 하나로 취급
        · 단일 자세 변형 : 형상을 안 바꾸고 반복 측정만
      → 따름정리 2가 "rank 4 를 못 넘는다" 고 예측한 그 실패를
        직접 보여줍니다. 이론과 실험이 맞물리는 가장 강한 그림입니다.

   ② VLM baseline 하나만  (PUGS 또는 SiPhy 중 세팅이 쉬운 쪽)
      → "추측 대신 측정" 을 뒷받침하는 데는 하나면 충분합니다.

   ③ PhysX-Omni  ← 여유 있으면
```

**①이 ②③보다 논문에 더 중요합니다.** 이론이 예측한 실패를 실제로 보이는
것이라, 리뷰어에게 "분석이 살아 있다" 는 증거가 됩니다. 그리고 우리 코드
안에서 스위치 하나로 됩니다.
