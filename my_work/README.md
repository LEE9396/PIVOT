# 밀도 추정 시뮬레이션 실행 가이드

Drake를 처음 쓰는 사람이 그대로 따라 할 수 있도록 정리한 문서입니다.
환경 설치는 이미 끝나 있으니, 아래 순서대로만 하면 됩니다.

> **코드가 무슨 일을 하는지부터 알고 싶다면** 맨 아래
> [부록: 코드 전체 이해하기](#부록-코드-전체-이해하기-고등학생용) 를 먼저 읽으세요.
> 수식 없이, 파일 하나하나가 무슨 역할인지 순서대로 설명합니다.

## 0. 미리 알아둘 것

### 실행 명령의 생김새

모든 명령은 이 형태입니다.

```bash
../robot_learning/scripts/run_drake_env.sh python <파일이름>
```

앞의 `run_drake_env.sh`는 **Drake가 설치된 파이썬을 골라주는 역할**만 합니다.
이 컴퓨터에는 파이썬이 여러 개(시스템, conda, ROS 2) 깔려 있어서,
그냥 `python`이라고 치면 Drake가 없는 파이썬이 잡혀 `ModuleNotFoundError`가 납니다.

### `conda activate`는 쓰지 마세요

이 컴퓨터는 터미널을 열 때마다 ROS 2 Jazzy와 CUDA 경로가 자동으로 잡힙니다.
`run_drake_env.sh`는 그것들을 잠시 걷어내고 실행하는데, `conda activate`는 그걸 안 합니다.
지금 당장은 둘 다 동작하지만, 나중에 예고 없이 깨질 수 있으니 위 형태를 습관으로 쓰세요.

### 파일 위치

| 파일 | 내용 |
| --- | --- |
| `density_id_drake.py` | 알고리즘 본체 (desk lamp 예제) |
| `view_density_id.py` | 시각화 뷰어 |
| `figures/convergence.png` | 실행하면 생기는 수렴 그래프 |
| `frames/` | 렌더링하면 생기는 자세별 이미지 |
| `density_id_objects.py` | **실제 2-link / 3-link 물체 검증** (9장 참조) |
| `check_object_geometry.py` | 위 모델이 CAD 치수와 맞는지 확인 |
| `outputs/results_objects.txt` | 검증 결과 기록 |

## 2. 알고리즘 실행하기

```bash
../robot_learning/scripts/run_drake_env.sh python density_id_drake.py
```

10초 안에 끝납니다. 아래처럼 나오면 성공입니다.

```
parts: ['base', 'counterweight', 'lower_arm', 'upper_arm', 'head']
true densities [kg/m^3]: [2700. 7800. 1200.  900. 4500.]

structural identifiability (singular values of stacked, whitened C):
  [2.69  0.708 0.461 0.107 0.051]  -> rank 5/5

round |   active: theta*     RMSE  maxRel% | random RMSE ...
    1 |    [-0.53 -1.73]   3041.7    98.5% | ...
    ...
    6 |      [-1.6  0. ]     11.2     2.1% | ...

final estimate (active selection):
  base           true  2700.0  est  2697.9  err  0.08%
  ...
saved plot -> figures/convergence.png
```

### 출력 읽는 법

- **`rank 5/5`** — 5개 파트 밀도가 원리상 모두 구분 가능하다는 뜻. 여기서 rank가 5보다
  작게 나오면 아무리 측정해도 일부 파트는 못 맞춥니다.
- **`round` 표** — 측정을 한 번씩 늘려가며 오차가 줄어드는 과정. 왼쪽이 알고리즘이
  똑똑하게 자세를 고른 경우, 오른쪽이 무작위로 고른 경우입니다. 왼쪽 숫자가 더 작아야
  알고리즘이 이긴 겁니다.
- **`final estimate`** — 파트별 최종 정답 대비 오차.

## 9. 실제 2-link / 3-link 물체로 검증하기

`density_id_drake.py`의 desk lamp는 알고리즘 시연용 가상 물체입니다.
실제로 출력할 두 물체에 **part별로 서로 다른 밀도 GT**를 부여해 검증하려면:

```bash
# CAD 치수와 맞는지 먼저 확인 (링크 간격 4 mm, 전체 길이)
../robot_learning/scripts/run_drake_env.sh python check_object_geometry.py

# 밀도 식별 검증
../robot_learning/scripts/run_drake_env.sh python density_id_objects.py

# 자세를 그림으로 확인
../robot_learning/scripts/run_drake_env.sh python density_id_objects.py --render

# 한쪽만
../robot_learning/scripts/run_drake_env.sh python density_id_objects.py --object 2link
```

### 부여한 밀도 GT

| 물체 | part | 외부 부피 | 밀도 GT | 질량 |
| --- | --- | ---: | ---: | ---: |
| 2-link | parent | 138.0 cm³ | 1800 | 248.4 g |
| | child | 110.4 cm³ | 3600 | 397.4 g |
| 3-link | link0_base | 288.12 cm³ | 5200 | 1498.2 g |
| | link1_elbow | 208.40 cm³ | 1400 | 291.8 g |
| | link2_tip | 162.28 cm³ | 700 | 113.6 g |

밀도를 바꾸려면 `density_id_objects.py` 상단의 `TWO_LINK` / `THREE_LINK`
정의에서 `Part(...)`의 네 번째 인자를 고치면 됩니다. 바꾼 뒤에도 힌지
정지토크(0.9 N·m) 여유가 자동으로 다시 계산되어 출력됩니다.

### 무엇을 검증하는가

1. **기하** — q=0에서 링크 간격이 4.000 mm, 전체 길이가 139 / 353 mm로
   README와 일치하는지
2. **하드웨어 실현 가능성** — 그 밀도로 만들었을 때 Southco 힌지
   0.9 N·m를 넘지 않는지. 관절각 격자 × 중력 3방향을 전수 스윕하며
   Drake의 `CalcGravityGeneralizedForces`로 직접 계산합니다
3. **식별성** — 세 part 밀도가 원리상 구분 가능한지 (rank, 조건수)
4. **추정 정확도** — active(D-optimal) vs random을 **같은 노이즈 seed
   10개**로 비교

### 탐색 과정을 눈으로 보기

알고리즘이 자세를 고르는 과정을 Meshcat으로 재생합니다.

```bash
# 2-link (플라스틱 힌지 0.2 N·m 기준)
../robot_learning/scripts/run_drake_env.sh python explore_view.py \
  --object 2link --hinge-torque 0.2

# 3-link (0.5 N·m 이상 필요)
../robot_learning/scripts/run_drake_env.sh python explore_view.py \
  --object 3link --hinge-torque 0.5
```

`http://localhost:7000`을 브라우저에서 연 뒤 터미널에서 Enter를 누르면
라운드마다 세 단계가 재생됩니다.

1. **탐색** — 후보 격자를 훑습니다. 관절이 고정되지 않는 자세는 아예
   후보에서 빠져 있어 나타나지 않습니다. 터미널에 정보이득 상위 3개가
   출력됩니다
2. **선택** — 정보이득이 가장 큰 자세에서 멈춥니다. 그 자세의 관절토크와
   한계값이 함께 출력됩니다
3. **측정** — 중력 3방향으로 물체가 기웁니다. 로봇이 손목을 돌려 물체를
   다시 세우는 동작에 해당합니다. 빨간 화살표(중력)는 항상 아래를
   가리키고 물체가 대신 회전합니다

라운드가 끝날 때마다 현재 추정값과 GT, 사후 표준편차가 출력됩니다.

`--pace`로 후보 하나를 보여주는 시간을 조절합니다 (기본 0.08초).
`--rounds`로 라운드 수를 바꿉니다 (기본 4).

### 힌지를 바꿔 검증하기

현재 기본 힌지는 명가철물 힘조절경첩 HP-TC (PA6 플라스틱)입니다.
제조사가 토크를 공개하지 않으므로 **토크 게이지 실측값을 넣어야** 합니다.

```bash
# 토크별 가능 여부 표
../robot_learning/scripts/run_drake_env.sh python density_id_objects.py --sweep

# 실측 토크로 검증 (밀도를 자동으로 낮춰 관절이 고정되게 함)
../robot_learning/scripts/run_drake_env.sh python density_id_objects.py \
  --hinge-torque 0.25 --auto-scale
```

실험이 성립하는 최소 토크는 **2-link 0.036 N·m, 3-link 0.190 N·m**입니다.
이 아래로는 추를 다 빼도 관절이 미끄러져 어떤 밀도로도 실험할 수 없습니다.
자세한 내용은 `outputs/results_mg_plastic_hinge.txt` 참조.

## 10. 로봇이 실제로 잡고 하는 측정 (작업자 절차)

물체만 공중에 띄운 검증과 달리, 실제 실험은 RB5가 PGC 그리퍼로 물체를 잡고
손목을 돌려 자세를 만듭니다. 그리고 **물체의 관절각은 사람이 손으로 조정**합니다.
그래서 절차를 둘로 나눴습니다.

### 1단계 — Drake로 후보 자세를 미리 계산

```bash
../robot_learning/scripts/run_drake_env.sh python robot_scene.py \
  --object 3link --joint-range-deg 20 150 \
  --hinge-torque 0.5 --auto-scale --steps 5 --rounds 4 \
  --plan outputs/plan_3link.json
```

세 가지를 모두 통과한 자세만 남깁니다.

1. **힌지가 버티는가** — 중력 3방향에서 관절 토크 ≤ 유지토크 / 안전배수
2. **로봇이 도달하는가** — 역기구학 해가 존재하는가
3. **충돌이 없는가** — 팔·그리퍼·물체·테이블 최소거리 ≥ 6 mm

그리고 **시작 자세**를 하나 고릅니다. 작업자가 물체 관절을 움직이는 동안
로봇이 멈춰 있을 자세이므로, **구동범위 전 구간에서 충돌이 없어야** 통과합니다.

결과는 JSON 계획으로 저장됩니다 — 라운드별 목표 관절각, 시작 자세,
중력 3방향 각각의 팔 자세.

`--joint-range-deg`로 구동범위를 직접 지정합니다. 값 2개면 전 관절 공통,
관절 수 × 2개면 관절별로 다르게 줍니다. 힌지의 물리 한계를 벗어나면 거부합니다.

### 2단계 — 작업자 인터페이스로 실행

```bash
../robot_learning/scripts/run_drake_env.sh python operator_ui.py \
  --plan outputs/plan_3link.json
```

라운드마다 이 순서로 진행됩니다.

| 단계 | 표시등 | 로봇 | 작업자 |
| --- | --- | --- | --- |
| 시작 자세로 이동 | 🔴 빨강 | 이동 중 | 접근 금지 |
| 시작 자세 도달 | 🟢 초록 | **정지** | 접근 가능 |
| 관절각 조정 | 🟢 초록 | **정지** | 슬라이더로 목표 각도에 맞춤 |
| 각도 확인 | 🟢 초록 | **정지** | ① 조정 완료 클릭 |
| 안전 확인 | 🟢 초록 | **정지** | ② 손을 뗐습니다 클릭 |
| 측정 | 🟠 주황 | 중력 3방향 이동 | 접근 금지 |

안전 장치가 둘입니다.

- **각도 검증** — ① 을 눌러도 슬라이더 값이 목표와 ±3° 안에 들지 않으면
  거부하고 다시 맞추라고 합니다
- **2단 확인** — ② 를 누르기 전에는 로봇이 절대 움직이지 않습니다.
  "손을 뗐다"는 사실을 작업자가 명시적으로 선언해야 이동이 시작됩니다

표시등은 Meshcat 화면 안의 색 패널이고, 같은 내용이 터미널에도 박스로 출력됩니다.

절차만 점검하려면 `--self-test`를 붙이세요. 작업자 입력을 자동으로 대신합니다.

### 이 실험이 두고 가는 가정

| 가정 | 근거 |
| --- | --- |
| **밀도가 균일하다** | 실험 전제. 추정기가 푸는 미지수가 곧 평균 밀도입니다 |
| **관절각은 고정 후 유지된다** | 실시간 추적을 쓰지 않습니다. 시작 지점에서 작업자가 한 번 고정하고, 그 각도가 유지된다고 봅니다 |
| **가시성은 문제되지 않는다** | 관측이 시작 지점에서만 일어나므로, 탐색 중 팔이 물체를 가려도 무관합니다 |

두 번째 가정을 지켜 주는 것은 **힌지의 유지토크뿐**입니다. 추적이 없어서
각도가 흘러도 알아챌 방법이 없기 때문입니다. 그래서 계획은 라운드마다
**측정 중 힌지가 견뎌야 할 최악 토크와 여유배수**를 기록하고 화면에 띄웁니다.

```
* 측정 중 힌지가 견뎌야 할 최악 토크 0.289 N·m / 한계 0.333 N·m  (여유 1.7x)
```

여유가 낮은 라운드가 각도가 흐를 위험이 큰 라운드입니다. 결과가 이상하면
이 숫자로 의심 구간을 좁힐 수 있습니다.

추정식에는 **목표 각도가 아니라 작업자가 실제로 맞춘 각도**가 들어갑니다.

균일밀도 가정이 깨졌을 때의 영향을 보려면 `--com-mismatch`를 켜세요.
전제가 아니라 강건성 점검이므로 기본은 꺼져 있습니다.

## 참고: 이건 "동역학 시뮬레이션"이 아닙니다

`--live`에서 팔이 움직이는 건 자세와 자세 사이를 부드럽게 이어 붙여 보여주는 것이지,
실제로 힘을 받아 움직이는 계산이 아닙니다.

원래 알고리즘이 **각 자세에서 가만히 멈춘 상태의 힘/토크만** 측정하는 구조라
(`time_step=0.0`, `Simulator` 미사용) 그 사이의 움직임은 정의되어 있지 않습니다.
실제로 팔이 흔들리고 가속하는 과도응답까지 보려면 `Simulator`와 관절 제어기를
추가해야 하며, 이는 알고리즘을 정적(quasi-static)에서 동적으로 확장하는 별도 작업입니다.

# 부록: 코드 전체 이해하기 (고등학생용)

수식은 꼭 필요한 것 하나만 씁니다. 나머지는 전부 말로 설명합니다.

---

## 1. 우리가 풀려는 문제

로봇이 처음 보는 물건을 집었습니다. 노트북 같은, 접히는 물건입니다.

이 물건을 시뮬레이터 안에 똑같이 만들어 넣으려면 **각 부위가 얼마나 무거운지**
알아야 합니다. 화면 덮개가 100 g 인지 500 g 인지에 따라, 시뮬레이터 안에서
물건이 넘어지는 모습이 완전히 달라지기 때문입니다.

카메라로는 **모양**만 보입니다. 겉모양이 같아도 속이 빈 플라스틱일 수도,
납덩이일 수도 있습니다. **무게는 만져 봐야 압니다.**

그래서 이 코드는 이렇게 합니다.

> 로봇이 물건을 잡고 몇 가지 자세로 기울여 본다.
> 손목에 달린 힘 센서가 읽은 값으로, 부위별 밀도를 역산한다.
> 그 밀도로 질량·무게중심·관성모멘트를 계산해 URDF 파일로 내보낸다.

URDF 는 시뮬레이터가 읽는 물체 설명서입니다. 이게 최종 산출물입니다.

---

## 2. 왜 어려운가 — 저울 하나로 세 개를 재기

물건이 부위 3개(A, B, C)로 되어 있다고 합시다. 손목 센서는 **전체가 만드는
힘과 토크 하나**만 읽습니다. 부위별로 따로 읽어주지 않습니다.

가방에 사과·배·귤을 넣고 통째로 저울에 올린 것과 같습니다. 총 무게 1 kg 은
알아도, 사과가 몇 g 인지는 모릅니다.

**그런데 관절을 접으면 이야기가 달라집니다.**

가방을 손으로 들고 있다고 상상해 보세요. 사과를 손 가까이 옮기면 팔이 덜
힘들고, 멀리 옮기면 더 힘듭니다. **무게는 그대로인데 손목이 느끼는 비틀림
(토크)이 달라집니다.** 이 차이가 "사과가 얼마나 무거운지"를 알려줍니다.

관절 각도를 바꾸면 각 부위가 손목에서 얼마나 멀어지는지가 바뀝니다.
자세를 여러 번 바꿔 재면, 미지수 3개짜리 연립방정식이 만들어집니다.

```
자세 1에서 재면 :  0.29·ρA + 0.21·ρB + 0.16·ρC = (측정값 1)
자세 2에서 재면 :  0.29·ρA + 0.05·ρB - 0.11·ρC = (측정값 2)
자세 3에서 재면 :  ...
```

앞의 숫자(0.29, 0.21, …)는 **부피와 위치에서 나오는 값**이라 카메라와 CAD 로
계산할 수 있습니다. 우리가 모르는 건 ρ(밀도)뿐입니다.

이게 이 코드의 전부입니다. 나머지는 전부 "그럼 어떤 자세로 재는 게 제일
이득인가"와 "센서가 흔들리는데 어떻게 믿을 만한 답을 내는가"입니다.

---

## 3. 딱 하나의 수식

```
y  =  A(θ) · ρ  +  잡음
```

| 기호 | 읽는 법 | 정체 |
| --- | --- | --- |
| `y` | 와이 | 손목 센서가 읽은 값. 힘 3개 + 토크 3개 = 6개 숫자 |
| `ρ` | 로 | **우리가 찾는 것.** 부위별 밀도 (부위가 3개면 숫자 3개) |
| `θ` | 세타 | 물체의 관절 각도. 사람이 손으로 맞춰 준다 |
| `A(θ)` | 에이 | 위 연립방정식의 계수표. 각도 θ 에 따라 값이 바뀐다 |

`A(θ)` 를 만들려면 각 부위의 **부피**와 **무게중심 위치**가 필요합니다.
부피는 CAD 에서 읽고, 위치는 Drake 가 관절 각도로부터 계산해 줍니다.
밀도는 하나도 필요 없습니다 — 그래서 정답을 몰라도 계수표를 만들 수 있습니다.

**중력 방향 3개를 씁니다.** 로봇이 손목을 돌려 물건을 아래로, 옆으로, 앞으로
기울입니다. 한 번의 "라운드"마다 6 × 3 = 18 개의 숫자를 얻습니다.

---

## 4. 파일 지도 — 누가 무슨 일을 하는가

각 파일을 "팀에서 한 사람"이라고 생각하면 이해가 빠릅니다.

### 물체와 물리를 담당하는 사람들

| 파일 | 역할 | 비유 |
| --- | --- | --- |
| `density_id_drake.py` | 수식 `y = A(θ)ρ` 를 실제로 계산 | **계산기** |
| `density_id_objects.py` | 실물 2-link / 3-link 의 CAD 치수를 코드로 옮김 | **설계도 보관함** |
| `nlink.py` | 부위 수를 2~8개로 늘린 가짜 물체를 만듦 (실험용) | **연습 문제 출제자** |

`density_id_objects.py` 에는 CAD 에서 읽은 숫자가 그대로 들어 있습니다.
예를 들어 3-link 물체의 첫 번째 부위는 이렇게 적혀 있습니다.

```python
Part("link0_base", (150.0, 44.0, 44.0), 288.12, 5200.0, ...)
#     이름          가로세로높이 [mm]    부피[cm³]  밀도 GT
```

**밀도 GT(5200)는 "정답"입니다.** 실물에서는 절대 알 수 없는 값이고,
코드도 추정할 때는 이 값을 보지 않습니다. 마지막에 "잘 맞췄나" 채점할 때만
씁니다. 코드 곳곳에 `GT 는 채점에만` 이라는 주석이 붙어 있는 게 그 뜻입니다.

### 로봇과 안전을 담당하는 사람들

| 파일 | 역할 | 비유 |
| --- | --- | --- |
| `robot_scene.py` | 로봇팔·그리퍼·책상·카메라를 배치하고 IK 를 품 | **작업장 관리인** |
| `path_planning.py` | 두 자세 사이 부딪히지 않는 길을 찾음 | **길 안내** |
| `operator_ui.py` | 화면에 신호등·버튼·슬라이더를 띄움 | **안전 요원** |

**IK(역기구학)** 는 "손끝을 여기에 두려면 팔 관절을 몇 도씩 꺾어야 하나"를
푸는 것입니다. 사람은 무의식으로 하지만 로봇은 계산해야 합니다.

**경로 계획(RRT-Connect)** 은 미로 찾기입니다. 출발점과 도착점 사이에 무작위
점을 뿌려 가며 부딪히지 않는 길을 잇습니다. 처음엔 직선으로 이으려 했는데
책상을 62 mm 뚫고 지나가서 이 방식으로 바꿨습니다.

### 알고리즘의 두뇌

| 파일 | 역할 |
| --- | --- |
| `angle_aware.py` | 각도 측정 오차를 계산에 반영 |
| `design_core.py` | **핵심.** 다음 자세 고르기 · 밀도 풀기 · 언제 멈출지 판단 |

나뉘어 있습니다.

```
1. 기본량        A(θ) 만들기, 측정 잡음 계산
2. 선택 기준     D / A / E — "어떤 자세가 이득인가"를 재는 세 가지 자
3. 후보 선택     격자 vs 연속 최적화 — "그럼 어디로 갈까"
4. 추정기        WLS vs TLS — "측정값에서 밀도를 어떻게 뽑아낼까"
5. 정지 조건     "이만하면 됐다"를 언제 말할까
6. 폐루프        위 다섯을 순서대로 돌리는 반복문
```

`dual_view.py` 를 실행하면 브라우저 창이 두 개 열립니다.

한 라운드는 이렇게 흘러갑니다.

```
[왼쪽]  ① 지금까지 알아낸 밀도로 "다음엔 어떤 각도가 제일 이득인지" 계산
              └ design_core.continuous_best()
        ② "관절을 45도, 180도로 맞춰 주세요" 를 오른쪽으로 전달

[오른쪽] ③ 로봇이 시작 자세로 이동하고 멈춤 — 화면에 초록 신호등
        ④ 사람이 손으로 물체 관절을 맞춤 (슬라이더로 조작)
        ⑤ 사람이 "안전합니다" 버튼 두 개를 누름
        ⑥ FoundationPose(카메라)가 실제 각도를 측정  ← 명령한 각도가 아님!
        ⑦ 그 측정 각도로 IK 를 풀고, 그 형상 그대로 경로를 계획
        ⑧ 천천히(준정적으로) 이동해 중력 3방향으로 재기

[왼쪽]  ⑨ 받은 측정값으로 밀도를 다시 풀고 불확실성을 갱신
        ⑩ 목표에 닿았으면 멈추고, 아니면 ①로
```

### ⑥번이 왜 중요한가

사람이 "45도"로 맞춰도 실제로는 44.7도일 수 있고, 카메라가 그걸 45.3도로
읽을 수도 있습니다. **로봇은 실제 각도를 알 방법이 없습니다.** 카메라가 준
값이 전부입니다.

그래서 코드는 두 값을 엄격히 나눠 둡니다.

```python
self.object_q_deg    # 실제 각도 — 물리(센서가 읽는 값)에만 쓴다
self.believed_q_deg  # 카메라가 읽은 각도 — IK·경로계획에 쓴다
```

이걸 섞으면 시뮬레이션에서는 잘 되는데 실물에서 로봇이 멈춥니다.

그리고 ①에서 자세를 고를 때도 이걸 고려해야 합니다. "45도에서는 로봇이
잡을 수 있다"만 확인하고 보내면, 카메라가 45.3도로 읽는 순간 로봇이 못
잡아서 라운드가 통째로 날아갑니다. 그래서 코드는 **명령 각도 하나가 아니라
각도 오차의 95% 구간 모서리까지 전부 확인**하고, 그 안에서 여유 있게 잡을
수 있는 자세만 고릅니다. 이 검사를 넣기 전에는 6라운드 중 4라운드가
중단됐고, 넣은 뒤에는 2라운드 만에 끝납니다.

## 6. 알고리즘의 네 가지 핵심

### 6-1. 불확실성이란 무엇인가

코드는 밀도를 하나의 숫자로만 갖고 있지 않습니다. **"5200 언저리인데, ±120
정도는 모르겠다"** 처럼 폭을 함께 갖고 있습니다. 이 폭이 불확실성입니다.

처음에는 폭이 아주 넓습니다. 물건을 저울에 올려 총무게만 재고 시작하면,
"모든 부위가 평균 밀도 2889 kg/m³ 일 것 같은데, 사실 잘 모르겠다"가 출발점입니다.

측정할 때마다 폭이 줄어듭니다. 폭이 목표(예: ±1%)보다 작아지면 멈춥니다.

### 6-2. 다음 자세를 어떻게 고르나 (능동 탐색)

아무 각도나 재면 되는 게 아닙니다. **어떤 각도는 정보를 많이 주고, 어떤
각도는 거의 안 줍니다.**

극단적인 예로, 관절 축과 중력이 나란하면 그 아래 있는 부위가 만드는 토크가
0 이 됩니다. 아무리 재도 그 부위의 무게가 안 보입니다.

그래서 매 라운드 이렇게 합니다.

> "지금 내가 아는 밀도가 이 정도라면, 각 각도에서 재면 불확실성이 얼마나
> 줄어들까?" 를 전부 계산해 보고, 가장 많이 줄어드는 각도를 고른다.

이걸 **정보이득이 최대인 자세**라고 부릅니다.

예전에는 각도를 5칸씩 잘라 격자를 깔고 그중 최고를 골랐습니다. 지금은
**연속 최적화**로 격자에 얽매이지 않고 찾습니다. 격자를 441칸으로 잘게 썰어야
나오는 값을 절반의 계산으로 찾아냅니다.

### 6-3. 밀도를 어떻게 푸나 (WLS vs TLS)

연립방정식을 푸는 건데, 문제는 **계수표 `A(θ)` 자체가 조금 틀려 있다**는
점입니다. 각도를 카메라가 ±5% 오차로 재주기 때문입니다.

마트 영수증으로 비유해 봅시다.

> `총액 = 개수 × 단가` 에서 단가를 구하려고 합니다.
> 그런데 **개수를 세는 사람이 가끔 틀립니다.**

- **WLS (예전 방식)**: 개수는 맞다고 치고, 개수가 틀린 몫을 "총액 쪽 오차"로
  떠넘깁니다. 그러면 단가가 **한쪽으로 치우칩니다.** 영수증을 아무리 많이
  모아도 이 치우침은 안 없어집니다.
- **TLS (지금 방식)**: 개수도 미지수로 놓고 단가와 **같이** 풉니다.
  "개수가 틀렸을 수 있다"가 모형 안에 들어가므로 치우침이 사라집니다.

실험 결과(seed 40개):

```
라운드    WLS 치우침    TLS 치우침
   1       1.58%         1.14%
   2       0.59%         0.01%
   5       1.52%         0.00%
   8       1.41%         0.01%     ← 8번을 재도 WLS 는 안 줄어든다
```

예전에 "측정할수록 오차가 커지는 것 같다"고 하셨던 게 바로 이겁니다.

### 6-4. 언제 멈추나

실물에서는 정답을 모릅니다. 그러니 **"내가 얼마나 확신하는가"만 보고** 멈출지
정해야 합니다.

문제는 그 확신이 과장될 수 있다는 것입니다. 시험 문제를 풀고 "다 맞은 것
같다"고 했는데 실제로는 반만 맞은 상황입니다.

그래서 **잔차 팽창**을 씁니다.

> 내 모형이 맞다면, 예측값과 측정값의 차이(잔차)가 어느 정도여야 하는지
> 미리 알 수 있다. 실제 차이가 그보다 5배 크다면, 내 잡음 모형이 그만큼
> 낙관적이었다는 뜻이다. 그 비율만큼 불확실성을 부풀린다.

이건 **정답을 몰라도 데이터만으로 계산됩니다.** 그게 핵심입니다.

효과 (`적용률` = "95% 라고 말한 구간에 실제 오차가 들어온 비율"):

```
              분산만    +잔차팽창
WLS  round 5    3%        3%      ← 정지 조건을 고쳐도 소용없다
TLS  round 5   88%       99%      ← 추정기를 고치면 제자리를 찾는다
```

**WLS 는 정지 조건만 손봐서는 못 구합니다.** 오차가 "흔들림"이 아니라
"치우침"이라, 구간을 넓히면 "언제 멈춰도 틀린" 상태가 "틀렸다고 인정하는"
상태로 바뀔 뿐입니다.

## 7. 최근에 고친 여섯 군데

| | 무엇을 | 전 | 후 |
| --- | --- | --- | --- |
| ① | 후보 자세 | 격자 5칸씩 잘라 top-1 | 연속 최적화 |
| ② | 기울임 방향 | 아래·옆·앞 3방향 고정 | **그대로** (아래 설명) |
| ③ | 밀도 푸는 법 | WLS | **TLS** |
| ④ | 자세 고르는 기준 | D-최적 | **그대로 D** |
| ⑤ | 정지 조건 | 분산만 | **+ 잔차 팽창** |
| ⑥ | 자세 실현 검사 | 명령 각도 하나만 확인 | **각도 오차 구간 전체 확인** |

⑥은 ①의 부작용을 막는 것입니다. 연속 최적화는 격자와 달리 "미리 검증해
둔 자세 목록"이 없어서, 로봇이 아슬아슬하게만 잡을 수 있는 자세를 골라
버립니다. 카메라 오차가 조금만 얹히면 못 잡게 되고 라운드가 날아갑니다.

### ② 를 안 바꾼 이유

실험해 보니 **직교하는 3방향을 쓰는 한, 삼각대를 어떻게 회전시켜도 정보량이
정확히 같았습니다** (무작위 회전 200번, 차이 4e-10). 회전은 정보 면에서
공짜 자유도입니다.

그래서 회전을 다른 목적(관절 토크 37% 절감)에 쓸 수 있는데, 이 연구는
"관절이 절대 안 움직인다"는 전제라 토크를 아낄 이유가 없습니다.
게다가 방향을 바꾸면 로봇 손목 자세가 바뀌어 IK 와 도달 가능성이 흔들립니다.
**얻는 게 없고 잃을 게 있어서 그대로 뒀습니다.**

방향이 실제로 갈리는 건 3개 미만을 쓸 때입니다. 한 방향만 쓰면 어디로
기울이냐에 따라 정보량이 2.8배 차이 납니다.

### ④ 를 안 바꾼 이유

D / A / E 는 "불확실성 덩어리"를 각각 부피 / 지름의 합 / 가장 긴 지름으로
재는 세 가지 자입니다. 부위가 3개인 실물에서는 셋이 같은 답을 냅니다.

부위를 늘려 실험하니 **부위 4개부터 D 가 이겼습니다.**

```
부위    D      A      E     (목표에 닿기까지 라운드 수)
 4     3.5    5.6    7.9
 5    10.5   12.0   12.0
```

E 는 "가장 안 보이는 방향 하나"만 노리는데, 그걸 고치면 다음엔 다른 방향이
최악이 되고, 그걸 고치면 또 원래 방향이 최악이 됩니다. 돌려막기가 됩니다.
D 는 모든 방향을 한꺼번에 봐서 그 함정에 안 빠집니다.

## 9. 자주 나오는 질문

**Q. 정답(GT)을 코드가 몰래 쓰고 있는 건 아닌가요?**

아닙니다. GT 는 두 군데에서만 등장합니다.
(1) 가짜 측정값을 만들 때 — 실물에서는 진짜 물체가 대신하는 역할입니다.
(2) 맨 마지막 채점 — "추정값이 얼마나 맞았나" 를 사람에게 보여줄 때.

자세를 고르거나, 밀도를 풀거나, 멈출지 판단할 때는 절대 안 씁니다.
`study_*.py` 파일 첫머리에 이 원칙이 적혀 있습니다.

**Q. 관절이 움직이면 어떻게 되나요?**

이 연구는 **노트북·스탠드형 램프·폴더블 폰처럼 사람이 각도를 맞춰 두면
그대로 고정되는 물건**만 다룹니다. 각도가 흐르면 계수표가 틀려져서
추정이 망가집니다. 그래서 로봇도 준정적으로(아주 천천히) 움직입니다.

**Q. 왜 중력 방향이 3개인가요?**

한 자세에서 한 방향으로만 재면, 그 방향에 수직인 성분은 아무 정보도 안
줍니다. 세 방향을 직교하게 쓰면 3차원 공간을 빠짐없이 훑게 됩니다.
4개, 6개로 늘려도 이득이 거의 안 늘어납니다 (26.1 → 26.7 → 27.5 nat).

**Q. `준정적`이 무슨 뜻인가요?**

"거의 정지한 것처럼"입니다. 빨리 움직이면 가속도 때문에 관성력이 생겨서
센서가 중력 말고 다른 것도 읽습니다. 코드는 관성 토크가 중력 토크의 1%
미만이 되도록 이동 시간을 잡습니다.

**Q. 부위를 몇 개까지 다룰 수 있나요?**

지금 조건(각도 오차 ±5%)으로는 **4개까지**가 현실적입니다. 5개부터는
12라운드를 돌려도 목표 정밀도(1%)에 못 닿습니다. 기준을 바꿔서 될 문제가
아니라, 그만큼의 미지수를 가를 정보가 애초에 부족한 것입니다.
부위가 많은 물체로 가려면 카메라 각도 정밀도를 올려야 합니다.
