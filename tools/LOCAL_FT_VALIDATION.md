## 추정식에 6축 영점 명시 및 중복 차감 검증

원시 센서 입력의 측정식은 `y_raw = A(theta,g) rho + b(g)`이다.
`b(g)=[Fx0,Fy0,Fz0,Tx0,Ty0,Tz0]`는 해당 자세의 빈 공구 측정값으로,
공구 중력과 센서 오프셋을 포함한다. 알려진 b를 고정하면
`[A I] [rho;b] = y_raw`와 `A rho = y_raw - b`는 같은 방정식이다.
영점은 밀도에 곱하는 A의 계수를 바꾸는 값이 아니라 측정식의 가산항이다.
자세마다 자유로운 미지수 b를 추가하면 물체의 힘까지 b가 설명할 수 있으므로
이번 변경은 검증된 영점 측정값을 사용하는 기존 방식을 유지한다.

기존에도 `RobotScreen.read_one → TareTable.apply`에서 영점은 차감되고 있었다.
이번에는 `design_core.measurement_equation → PlannerScreen.update` 경계에서
실제 행렬과 `wrench_raw - tare_applied`를 함께 구성하도록 연결했다.
기존 전달값 `wrench`와 일치하는지 검사하고 WLS/TLS/잔차 계산 모두 같은
차감 결과를 사용한다. 센서를 사용하는 새 메시지는 `tare_required=True`를
기록하므로 원시값·영점 누락 시 진행하지 않는다. 순수 시뮬레이션의 물체 렌치는
기존대로 받는다. 배열 길이, 유한성, 차감 누락/중복은 추정 상태 갱신 전에 검사한다.

검증: `test_local_ft_check.py` 13개 통과, 수정 Python 파일 구문 검사 통과.
`replay_ft_matrix.py`의 전체 램프 TLS 검산도 각 방향에 합성 영점
`[3,5,46,0.12,-0.08,0.03]` N/N·m를 더한 원시값을 새 입구로 전달하도록 바꿨고,
영점 차감 후 이전 밀도/질량 복원 검사를 통과했다. 이 영점은 코드 시험용이며
실측 캘리브레이션 파일에 저장하지 않았다. 로봇 연결/이동/실행 중 UI 재시작은 하지 않았다.

이번 변경은 영점 적용의 계산/전달 일관성을 검증한다. b 자체의 정확도,
센서 좌표축의 실물 일치, 영점 불확실성의 별도 공분산 전파는 이 검사로 입증되지 않는다.

후보 평가와 공분산 계산, TLS, 편향 재적합의 각도 하한 전달 누락을 수정했다.

실물 총질량을 자산 GT에서 가져오던 부분을 없애고, TLS에서는 `V @ rho`로
함께 추정한다. TLS 야코비안에서 각도·파지점과의 상관을 포함한 밀도 공분산을
구한다. 결과 JSON에 사용한 1σ 가정과 공통 파지 오차 여부도 남긴다.

95% 절대 반폭(kg/m³), 상대 반폭(%), 밀도 구간은 같은 공분산과 잔차 팽창을
사용한다. **밀도 절대오차 `abs(rho_est - rho_reference)`는 별도 평가값**이다.
참조 밀도가 알려져 있어야 실제 오차를 계산할 수 있다. 합성 검산에서는 총질량이
맞아도 공통 파지 오차와 부위 밀도가 섞여 점 추정에 오차가 남았으며, 이를
구간이 포함하는지 검사했다. 1σ를 지정하는 것 자체가 정확도를 보장하지 않는다.

### 영점 모델과 적용 범위

`hardware.GravityTare`는 기존 `tare_check`의 강체 모델을 재사용한다.

```text
g_sensor = R_world_sensor.T @ [0, 0, -1]
F_empty  = b_force  + W_tool * g_sensor
T_empty  = b_torque + 9.81 * cross(first_moment_tool, g_sensor)
y_object = wrench_raw - [F_empty, T_empty]
y_object = A(updated_angles, g_sensor) @ rho + shared_grasp_term + noise
```

월드 중력은 고정한다. 센서가 회전하므로 센서 좌표로 표현한 중력만 바뀐다.
빈 공구 자료에서 구한 바이어스·질량·1차 모멘트는 파지 후 고정하며, 물체가
걸린 센서 값으로 다시 영점을 맞추지 않는다. 센서 취득 전후 실제 관절각으로
정지 여부를 확인하고, FK 중력을 영점 차감과 회귀행렬에 동일하게 전달한다.

현재 로더는 `ft_mount` 프레임·물리 검산 합격 기록·실측 중력 방향을 요구한다.
넓은 방향으로 외삽하는 오류를 막기 위해 최소 4자세, `[1,g]`의 rank 4 및
조건수 100 이하를 요구한다. 이는 구현의 보수적인 자료 채택 조건이다.
맞춤 잔차 노름 제한은 기존 0.5 N / 0.02 N·m를 재사용한다.
한 자세나 매우 좁은 자세 자료로 이 조건을 대신하지 않는다. 기존 ±2° 이동
제한을 자동으로 풀지 않으며, 넓은 캘리브레이션 이동은 아직 실행하지 않았다.

현재 `aft_tare_current.json`은 여전히 과거 검산 실패 파일이므로 새 모델에
채택되지 않는다. **구현 완료와 실물 영점 검증 완료는 다르다.** 유효한 빈 공구
다자세 기록, 별도 하중 검산, optical table 평면 선택/적용 및 현재 파지의
FoundationPose 준비가 남아 있다. 새 보정 계수의 오차·온도 드리프트까지 모두
확률모형으로 식별한 것은 아니므로 실제 구간 포함률도 후속 실험으로 확인한다.

### Optical table 선택 결과 확인 및 재선택 준비

사용자가 상판 선택을 완료한 뒤 생성된 `calibration/rb5_optical_table_20260907.json`은

채택하지 않았으며, 충돌 모델/로봇 이동/활성 F/T 영점은 변경하지 않았다.

`calibrate_table_rgbd.py`는 선택한 모서리의 볼록 경계를 표시/반환하도록 수정했다.
중복점·일직선·너무 작은 영역·안쪽 점은 거부하며, 잘못된 선택은 창을 닫지 않고
안내한다. 기존 평면 검산과 교차점/잘못된 점 검사 self-test가 통과했다.

노출된 평평한 상판만 선택하도록 새 창을 열었다. 결과 경로는

선택한 영역을 확인한 뒤 optical table을 기존 책상과 구분해 충돌 모델에
