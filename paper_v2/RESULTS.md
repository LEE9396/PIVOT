## E10. 부피 오차의 전파 — `exp_v2_volume.py` (`figures/v2/volume_propagation.json`, `fig_volume.png`)

**채점 규약 (중요)**: 측정은 항상 **참 plant** 에서 나오고, 추정기가 믿는 부피 `VOLUMES` 만
part 별로 ±delta 로 흔든다. 질량은 `m_hat_i = rho_hat_i * V_used_i` (추정기가 실제로 쓴 부피)로
채점하고, 밀도는 `rho_hat_i` 를 참 물리밀도 `m_true_i / V_true_i` 와 비교한다.
질량을 `V_true` 로 채점하면 없는 질량오차를 만들어내므로 그렇게 하지 않았다.

seeds=8, rel=5%, max_rounds=14. |오차|% 평균±표준편차:

| delta% | 2link 질량 / 밀도 | 3link 질량 / 밀도 | desklamp 질량 / 밀도 |
|---|---|---|---|
| 0 | 0.12 / 0.12 | 0.07 / 0.07 | 0.17 / 0.17 |
| 2 | 0.63 / **1.46** | 0.75 / **1.82** | 0.65 / **1.92** |
| 5 | 1.65 / **3.74** | 1.83 / **4.49** | 1.18 / **5.02** |
| 10 | 2.18 / **8.75** | 3.94 / **9.51** | 1.48 / **10.10** |
| 20 | 2.58 / **18.68** | 4.62 / **20.32** | 2.12 / **21.21** |
| 30 | 3.12 / **29.07** | 6.16 / **32.57** | 2.70 / **34.14** |

라운드 중앙값: 2link 1→7, 3link 2→3, desklamp 2→6. 수렴: delta=30% 에서 2link 7/8, **3link 5/8**.

해석적 관성 오차 (등방 오배율 가정, s^2):
delta 2% → 1.33% · 5% → 3.31% · 10% → 6.56% · 20% → 12.92% · 30% → 19.11%.

### ★ 정직하게 쓸 것 — 두 부차 주장은 근사적으로만 참이다
1. **밀도 오차는 delta 를 거의 정확히 1:1 로 따라간다.** (30% → 29.1 / 32.6 / 34.1%) 주장 그대로다.
2. **질량 오차는 밀도보다 훨씬 완만하지만 완전히 평평하지는 않다.** delta=0 의 ~0.1% 에서
   delta=30% 의 3~6% 까지 올라간다. 매 delta 에서 밀도 오차의 **5~10분의 1** 이다.
   원인은 버그가 아니라 유한자료 효과다 — `rho_hat = D^-1 rho_hat_original` 의 정확한 불변성은
   순수 최소제곱에서만 성립하고, **참 부피로 세운 MAP 사전분포**가 섞이면 상쇄가 부정확해지며
   그 어긋남이 delta 와 함께 커진다. 본문에서 "질량은 부피 오차에 **엄밀히** 불변"이라고 쓰면 안 된다.
   "훨씬 덜 민감하다 / 1차적으로 불변" 이 정확한 표현이다.
3. **라운드 수는 delta 와 함께 뚜렷이 늘어난다** (가설과 다름). part 별 부호가 무작위라
   어떤 part 의 `V_used` 가 줄어들면 그 열의 정보량이 떨어지고, 최악 part 가 라운드 수를 끌어올린다.
   delta=30% 에서는 3link 8개 seed 중 3개가 14라운드 예산 안에 수렴하지 못했다.
   → **부피 정제가 필요한 이유가 하나 더 생긴 것이다**: 밀도·관성의 정확도뿐 아니라 **탐색 비용**도 부피에 달려 있다.

## E4b. 경로 실험의 ★ 중대한 주의사항 4건 (E4 표를 쓰기 전에 반드시 읽을 것)

1. **관절한계 위반 열은 해석적으로 죽은 열이다.** 두 방법 모두 항상 0 이고, 그럴 수밖에 없다 —
   관절한계는 볼록 상자이므로 한계 안의 두 IK 해를 잇는 직선은 상자를 벗어날 수 없고,
   RRT 도 상자 안에서만 표본을 뽑는다. v2 가이드라인이 Table 4 에 이 열을 요구하지만
   **"우리가 이겼다"로 제시하면 안 된다.** "직선 보간의 실패 방식은 관절한계가 아니라 충돌이다"라고
   명시적 non-issue 로 쓸 것.
2. **62 mm 일화를 "재현했다"고 쓰면 안 된다.** 재현한 최악 **테이블** 관통은 3link `link2_tip` 의
   **33.1 mm** 다. 더 큰 수치(desklamp 93.8 mm, 2link 83.5 mm)는 **물체-로봇팔** 관통이지
   테이블 관통이 아니다. 충돌 상대: 3link 기준 ft_mount 9회, robot link6 8회, table 6회.
   → "테이블 관통 33 mm, 로봇팔과의 관통은 최대 94 mm" 로 정확히 구분해 쓸 것.
3. **"정보량이 크면 기하학적으로 까다롭다"가 desklamp 에서 깨끗하게 성립한다.**
   ΔI 상위 8개 도달가능 configuration 이 정확히 직선 보간이 충돌하는 것들이고(최대 5쌍 중 4쌍),
   ΔI < 8.1 인 configuration 은 전부 직선이 깨끗하다. **기여 2의 전제를 직접 뒷받침하는 결과다.**
   3link 에서는 상관이 약하다(충돌이 격자 전반에 퍼짐) — 정직하게 함께 쓸 것.
4. **3link 의 백색화 회귀행렬 조건수는 모든 configuration 에서 ~1e17–1e18, 수치 rank 4/5 다.**
   버그가 아니라 구조다 — 단일 형상은 총질량 1 + 1차 모멘트 3 = 4개만 관측하는데 3link 는
   3 part + 2 힌지 = 미지수 5개다. **rank 4 천장이 조건수에 그대로 나타난 것**이므로
   Table 4 의 정보량 열에서 이것을 살릴 것. 2link(미지수 3)와 desklamp(미지수 3, 힌지 body 없음)는
   full rank 이고 조건수 9.9~324 다.

기타: 계획 실패율 0%, RRT 의 경로길이 추가분은 약 4% 에 불과하다.
설계 선택 — configuration 은 각 관절 전 범위를 관절당 5분할한 격자 전부(총 55개)를 썼다
(D-최적 선택분만이 아니라 전부. 그래야 ΔI-까다로움 상관과 IK 실패가 드러난다).
자세쌍은 `m0(-z)→m1(+x)→m2(+y)→m0` (triad) 와 `home→m0`, `m2→home` (transit) 를 분리 집계했다.
**주의**: `obj.get_spec("desklamp")` 는 기본 파지가 `pinch` 라 모든 격자점에서 IK 가 실패한다.
실제 파이프라인(`dual_view`)은 `--grasp centroid` 를 쓰며, 이 실험도 그렇게 했다.
