# 실물 로봇이 있어야만 되는 실험 — 실행 순서와 체크리스트

시뮬레이션으로 가능한 것은 모두 끝냈습니다. 아래는 **하드웨어가 있어야만** 채울 수 있는 칸입니다.
`my_work/hardware.py` 의 네 군데(`Rb5Driver`, `Aft200Sensor`, `FoundationPoseSensor`, `run_tare`)가
`NotImplementedError` 로 비어 있고, 그 클래스만 채우면 나머지 코드는 그대로 돕니다.

## 장비
6축 Rainbow Robotics RB5-850E / AIDIN AFT200-D80-C 손목 F/T / Robotiq 2F-85 / Intel RealSense D456.
세션마다 hand-eye 캘리브레이션 1회, 매 시행 전 그리퍼 tare (그리퍼가 일부 대상보다 무겁습니다).

---

## R1. 실물 밀도 추정 — **최우선** (Table 3 의 `Ours (real)` 열)

물체 순서가 중요합니다. **CAD 정답이 있는 물체로 코드를 먼저 검증**해야
오차가 재구성 탓인지 코드 탓인지 가릴 수 있습니다.

| 순서 | 물체 | 미지수 P | 예상 라운드 | 목적 |
|---|---|---|---|---|
| 1 | Custom 2-link | 3 | 1 | 파이프라인 디버깅. 가장 단순 |
| 2 | Custom 3-link | 5 | 2 | **이론 검증의 핵심** (단일형상 rank 4 < 미지수 5) |
| 3 | Stand lamp | 3 | 1 | 스캔 기반 재구성이 실물에서 도는지 |
| 4 | Laptop | 2 | 1 | 자산 제작 완료 후 |

```bash
# 작업 PC
cd ~/Desktop/PIVOT/my_work
../robot_learning/scripts/run_drake_env.sh python dual_view.py \
    --mode deploy --object 3link --bus tcp --bus-port 5555
# 로봇 PC
../robot_learning/scripts/run_drake_env.sh python robot_node.py \
    --host <작업PC IP> --port 5555 --hardware real
```

**최소 생존선**: 일정이 밀리면 **2-link 하나만이라도**. 1라운드면 끝나고
"이론 예측이 실물에서 맞는다"는 한 점은 확보됩니다.

## R2. 반복성 (R1 에 끼워 넣음)
사람이 손으로 관절각을 맞추는 절차이므로, **같은 물체를 3~5회** 돌려 추정이 일관되는지 봅니다.
안 하면 "운이 좋았던 것 아닌가"가 남습니다. 추가 비용은 세션 몇 번뿐입니다.

## R3. 소요 시간 · 사용자 개입 로그 (Table 5, 공짜)
코드가 이미 라운드마다 시각을 찍습니다(`t_select`, `t_est`). 추가로 필요한 것은
**사람이 관절을 맞추는 시간**을 따로 재는 것입니다. 논문 문장이
"물체당 평균 N회, 회당 약 M초"를 요구하므로 이 두 값이 있어야 합니다.
로봇 이동 시간과 사람 개입 시간을 **반드시 나눠서** 기록하십시오 — "최소 개입" 주장의 근거입니다.

## R4. 측정 경로 실주행 (Table 4 의 실측 열)
시뮬레이션에서 직선 보간 대비 RRT 의 우위는 이미 정량화했습니다.
실물에서 확인할 것은 **계획한 경로가 실제로 충돌 없이 실행되는가**와
**관절에 걸리는 최대 토크가 예측 범위 안인가** 입니다.
삼면체 회전의 자유도로 최대 관절토크를 39.9% 줄일 수 있다는 시뮬 결과를
실물 힌지(Southco 정지토크 0.9 N·m)에서 확인하면 "관절을 손상시키지 않는다"가 실증됩니다.

## R5. sim-real 거동 영상 (Fig. 7 의 실물 열) — **논문 제목의 절반이 걸린 실험**
현재 Fig. 7 은 **시뮬-시뮬 대리 검증**입니다. "sim-ready" 를 정당화하는 유일한 직접 근거가 이것입니다.

가장 저렴한 형태: **관절을 놓았을 때 중력으로 처지는 궤적**.
마찰 유지 관절이라 천천히 처지므로 촬영과 재현이 쉽고, 초기 관절각은 트래커가 이미 읽고 있습니다.
1. 추정이 끝난 직후 그 자리에서 관절을 놓고 촬영 (물체당 1~2분)
2. 같은 초기조건으로 시뮬레이션 재생 — 우리 추정 밀도 / vision baseline 밀도 / 균일 밀도
3. 궤적을 겹쳐 그림

넘어뜨리기·떨어뜨리기까지 하면 더 좋지만, 처짐만으로도 그림 하나는 나옵니다.

## R6. GT 확정 (조건부)
`gt_list.md` 가 최종 확정본이면 **불필요**합니다. 다만 아래 항목은 확인이 필요합니다.
- **DATA_NOTE.md 참조**: gt_list.md 의 램프 3개 part 와 노트북 Base 의 **밀도 열이 부피 열과 맞지 않습니다.**
  밀도가 옛 부피로 계산되어 있습니다. 어느 쪽이 최신인지 확인해 주십시오.
- custom object 질량이 pre-ballast 예비값인지 확정값인지.
- 램프를 아직 분해하지 않았다면, 분해 시 **배수법으로 part별 부피도 함께 실측**하십시오.
- 노트북은 분해하지 않는 전제이므로 **기지 추(50 g) 부착 후 차분**으로 part attribution 을 검증합니다.

## 한 세션에 묶어서 처리하는 순서
R1·R2·R3·R5 는 **같은 세션 안에서** 처리할 수 있습니다. 물체마다:
1. 저울로 총질량 (사전분포)
2. 밀도 추정 폐루프                    -> R1
3. 같은 물체 3~5회 반복                -> R2
4. 라운드별 시각 + 사람 개입 시간 기록  -> R3 (대부분 자동)
5. 관절 놓고 처지는 영상 1~2분          -> R5
6. (램프) 분해 -> 저울 + 배수법         -> R6
7. (노트북) 기지 추 50 g 부착 후 2 반복 -> R6
